3 Membership panel — one place for assign · change · dates · pay · pause · cancel

Every action here already exists somewhere in the app — spread across the roster menu, the profile's Edit modal, the billing centre and the bulk price tool, in three vocabularies. The panel replaces the profile's Current membership card and becomes the front door. Rule: every dialog ends with a consequence line that says what will happen to Stripe, derived from the row and your choices — never typed. Money that would move today is always behind a checkbox naming the amount. Flip the state switcher and edit the dialogs: the sentences are the specification.

3aMembership panel · phone (393px) — switch the state

Headline + pill, one money sentence, a facts row, an action row whose set depends on the state, and a footer to Advanced billing (the billing centre, unchanged). The pill and every sentence read the active MemberSubscription row — never Member.status.

3aThe same panel on desktop (lg:col-span-2) — the five states, one under the other
3bAssign — pick the option, choose how they pay; the terms and the consequence follow

One dialog replaces Purchase membership (roster), Activate this setup now, Record payment & renew and Create offer (billing centre). It writes the draft fields the existing routes read, then calls the route the payment path names — one step, not two.

3cChange plan — B12's dialog, now for offline rows and across billing cycles too

Same interval on Stripe = B12 (price swap at the next invoice). A different interval is no longer a dead end: it is a two-step switch — end this one at the period end, start the new one the same day — run as one action. Offline rows change from the next payment.

3dChange dates — Stripe owns the cycle, so a Stripe row exposes only the end date

Toggle the row kind. Start and paid-through are read-only for Stripe rows (they are Stripe's facts); the end date maps to cancel_at, and clearing it is stated as "renews until cancelled".

3eRecord payment — offline rows only; "covers through" is derived and editable

Replaces the blank Already paid? card two sections down the billing centre. Prefilled from the row; one sentence says what the paid-through date does.

3fPause — a date or open-ended; Stripe's collection pauses with it

Today "Paused" is a status label with no date and no billing effect. Here it writes pausedAt/pausedUntil on the row, sets the sticky label, and pauses Stripe collection (pause_collection: void, resumes_at). Resume is one button; offline rows get their paused days back.

3gCancel — at the period end by default; "now" is explicit and says what isn't refunded

The profile's Edit → status "canceled" today cancels the local row and leaves Stripe charging. This calls the route that cancels both, records CANCELED with the plan and amount (Reports' churn), and keeps access until the paid date.

3hMake it free — the comp in one step

Reached from ⋯ or from a $0 override in Assign. Says the one thing that matters: this is a comp on purpose, not a leftover placeholder — the distinction the billing centre's CompToggle exists for.

rulesWhat every dialog has in common

Consequence line — last thing above the buttons, in the info tint. Derived from the row kind, your choices and live Stripe facts fetched by a preview GET. Warn tint when money moves today; danger tint when something can't be undone.

Money today = a checkbox naming the amount. Nothing else is gated.

Undo is stated — "You can resume any time" / "This can't be undone from here".

Disabled means explained — every greyed path carries its reason inline.

One vocabulary — membership, plan · option. "Setup" and "offer" retire from owner copy; "subscription" appears only inside Stripe consequence lines.

Audit — the note written to BillingAuditLog is the consequence line the owner confirmed.
